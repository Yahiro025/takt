# Step 2.7: sound packs (Mechvibes import + KEEBY's own format)

Goal (from the supervisor brief, on the user's behalf -- "I want to be able to
build this keeby (like https://getkeeby.com/) for my CachyOS", choice
"Mechvibes import + own format"): load community Mechvibes sound packs the
user downloads themselves, and let the user's own recordings use the exact
same format -- no second, KEEBY-specific config schema. Packs are discovered
on disk, decoded/normalized into the Step 2.6 `SoundBank` model, and can be
swapped at runtime without ever letting the PipeWire real-time thread touch
freed memory or block.

## Supported format

Mechvibes' own `config.json` is KEEBY's native format too -- there is no
second schema for the user's own recordings. `key_define_type` selects
`"single"` (one audio sprite, `defines[code] = [start_ms, duration_ms]`) or
`"multi"` (`defines[code] = "relative/file.ext"`, filenames may contain a
`{lo-hi}` brace range). Missing/absent `version` means v1: no per-key
release sounds, no fallback for undefined keys (they stay silent). `version:
2` adds a pack-wide default `sound`/`soundup` (used by any key without its
own define, multi mode only) and per-key release via a `"<code>-up"` key,
honored in both single and multi mode. `version >= 3` is rejected outright
(the format is a real, evolving Mechvibes draft KEEBY does not implement).

Example config for the user's own recordings (multi mode, v2, one explicit
per-key release, everything else falling back to the pack defaults):

```json
{
  "id": "my-recording",
  "name": "My Keyboard",
  "key_define_type": "multi",
  "version": 2,
  "sound": "press/default.wav",
  "soundup": "release/default.wav",
  "defines": {
    "57": "press/space.wav",
    "57-up": "release/space.wav"
  }
}
```

Dropped at `~/.local/share/keeby/packs/my-recording/` (with `press/`,
`release/` subfolders holding the referenced files), this is a complete,
loadable pack -- `keeby --list-profiles` will show it as `my-recording`.

### Key mapping

`map_mechvibes_code` (src/sound_pack.cpp:40) implements the iohook/
libuiohook code space Mechvibes uses: unprefixed codes equal evdev `KEY_*`
codes directly; a fixed table of 20 "extended" iohook codes (numpad Enter,
right modifiers, nav cluster, arrows, PrintScreen, Pause, etc. -- e.g.
`3612`->`KEY_KPENTER`, `57416`->`KEY_UP`, `3675`->`KEY_LEFTMETA`) maps to
their evdev equivalents. Numeric evdev codes are accepted for the legacy
keyboard range 0..255, `BTN_LEFT`/`BTN_RIGHT`/`BTN_MIDDLE` (272..274), and
`KEY_FN` (464); code 0 remains inert at playback. The unused gaps 256..271
and 275..463, plus all other unsupported codes, are skipped. `load_pack`
counts skips per pack and prints one diagnostic line (pack id + count)
rather than one line per key, and never fails the load because of them.

## Loading pipeline (`load_pack`, src/sound_pack.cpp:345)

Runs entirely off the RT thread (called from `EngineController::
set_profile` or `main.cpp`'s startup path, never from `AudioBoundary::
process`). Steps, in order:

1. Resolve `dir` with `weakly_canonical`, read `dir/config.json` (<= 1 MiB,
   else rejected), parse with nlohmann-json in non-throwing mode (a parse
   failure is a clean `std::unexpected`, not an exception).
2. Reject `version >= 3`. Determine `single`/`multi` and v1/v2.
3. Every referenced filename is resolved by `resolve_pack_file` (src/
   sound_pack.cpp:111): must be relative, no `..` component, and
   `weakly_canonical(pack_dir / rel)` must still resolve inside `pack_dir`
   (this also defeats a symlink whose target escapes the pack directory,
   since canonicalization follows it before the containment check) and
   name a regular file.
4. Each referenced file is decoded to float PCM at its own rate via
   libsndfile (`decode_audio_file`, src/sound_pack.cpp:127): mono is
   duplicated to stereo, >2 channels is rejected, files over 10 minutes are
   rejected before decoding (checked from the header, no wasted decode),
   and every decoded sample is clamped to [-1, 1] (lossy codecs can produce
   tiny inter-sample overs).
5. **Single mode**: the one sprite is decoded once; each `defines` entry
   slices it (`slice_sprite`, src/sound_pack.cpp:191) at the *sprite's own
   sample rate* first (exact frame boundaries -- `start_ms`/`duration_ms`
   converted to frames and clamped to `[0, sprite.frames]`; a non-positive
   duration, or a start past the end, is rejected), then resamples only
   that slice to 48 kHz with libsamplerate (`SRC_SINC_MEDIUM_QUALITY`) if
   the sprite isn't already 48 kHz. **Multi mode**: each referenced file
   (or each file in a `{lo-hi}` expansion, `expand_braces`, src/
   sound_pack.cpp:95) is resampled to 48 kHz whole, no slicing.
6. Every distinct clip/slice gets a low (0.92x) and high (1.08x) playback-
   rate pitch variant (`pitch_variant` -> `resample_to`, src/
   sound_pack.cpp:161/183), so every sounding key ends up with >= 3
   variants; a `{lo-hi}` group gets its own low/high pair *per file*, not
   one pair for the whole group.
7. **Dedup**: `PackBuildState::cache` (src/sound_pack.cpp:207) keys on the
   resolved file list (multi) or the exact `[start_ms, duration_ms]` pair
   (single), so two keys pointing at the same clip/slice -- including the
   v2 default `sound`/`soundup` fallback shared by every undefined key --
   share one `KeySound` range; the PCM (and its pitch variants) is decoded
   and stored exactly once.
8. `KeySound` limits are enforced with clear errors as they're built:
   `first` can't exceed 65535 (`kMaxSampleTableSize = 65536` samples total,
   checked before every push), `count` can't exceed 255 (checked as
   `variants_per_file * 3 > 255` before generating them).
9. `pan[code] = key_pan(code)` for every code.
10. `normalize_pack_loudness` (src/sound_pack.cpp:292) scales every sample
    in the finished bank by one global factor so the pack's peak lands at
    0.9, capped so it never boosts by more than 4x (a very quiet pack stays
    quiet rather than amplifying noise/silence).
11. `validate_sound_bank` (unchanged from Step 2.6) has the final word:
    range bounds, sample format, pan range.

Every step above returns `std::expected` on failure; `load_pack`'s body is a
single function-try-block catching `std::exception`/`...` as a last resort
(covers an nlohmann type-mismatch exception, e.g. `"version": "x"`, that
individual `is_string()`/`is_number()` guards don't already prevent), so a
malformed or hostile pack directory can never crash or throw out of
`load_pack` -- always a clean `std::unexpected<std::string>`.

### Limits and safety checks (pack directory is untrusted input)

| Limit | Value | Enforced by |
|---|---|---|
| `config.json` size | <= 1 MiB | size check before parsing |
| any one source file's length | <= 10 minutes | header check before decoding |
| whole pack's decoded float PCM | <= 256 MiB | running total in `push_sample` |
| samples in one pack | <= 65536 | `kMaxSampleTableSize`, before every push |
| variants for one key | <= 255 | before generating pitch variants |
| any final sample's length | <= 10 s (`kMaxSampleFrames`) | `validate_sound_bank` |
| path traversal / absolute paths | rejected | `resolve_pack_file` |
| symlink escaping the pack dir | rejected | `weakly_canonical` + containment check |
| non-regular files (fifo/device/dir) | rejected | `is_regular_file` check |
| malformed JSON / wrong field types | clean error | non-throwing parse + `is_*()` guards + outer catch |

## Real-pack compatibility fixes (packcompat patch, pkgrel 3)

Live-testing against the user's 18 downloaded Mechvibes packs
(`~/.local/share/keeby/packs`) found 4 that `load_pack` rejected even though
every other tool (including Mechvibes itself) loads them fine:
`eg-crystal-purple` and `eg-oreo` (single mode, `"3597": null` in `defines`
four times each), `nk-cream` (v2 multi, `"3597": null`), and `mxblue-travel`
(v2 multi, six per-key files that are genuinely absent upstream:
`press`/`release` x `BACKSPACE`/`ENTER`/`SPACE` -- confirmed by directory
listing, not a bug in this loader). `load_pack` was stricter than Mechvibes'
own semantics in two ways, both now fixed:

1. **`null` define values.** Mechvibes treats a `null` entry as "no sound
   for this key/direction" (single mode, v1 multi) or "use the pack
   default" (v2 multi, via its own `defines[key] ?? sound` fallback) --
   never an error. `load_pack` now checks `value.is_null()` before the
   type guard in both the single-mode and multi-mode `defines` loops
   (`src/sound_pack.cpp`) and simply `continue`s: in single mode and v1
   multi that leaves the key silent; in v2 multi it leaves
   `press[code].count`/`release[code].count` at 0, so the existing
   default-fallback loop (unchanged) fills it exactly as it would for a
   key absent from `defines` altogether.
2. **A per-key file that resolves but doesn't exist.** Previously any
   `resolve_pack_file` failure was a hard error, including plain
   "file not found" for one key in an otherwise-fine pack. Now only that
   specific outcome (`is_missing_file_error`, src/sound_pack.cpp) is
   downgraded: the affected key/direction is skipped (v2 multi falls back
   to the default the same way a null does; otherwise it stays silent) and
   a warning is recorded. Every other `resolve_pack_file` rejection --
   absolute path, `..`, symlink escape, non-regular file for a reason
   other than "missing" -- is untouched and still a hard `std::unexpected`,
   as is a missing single-mode sprite, a missing v2 default `sound`/
   `soundup` when the config actually references it, and (new) a pack that
   ends up with zero keys sounding on press at all
   (`"sound_pack: pack has no press sound for any key"`) -- a config that
   silently produces total silence is far more likely a mistake than an
   intentional pack.

**Warnings.** `load_pack(dir, warnings)` takes an optional
`std::vector<std::string>*` (default `nullptr`). Both the existing
skipped-unknown-key-code diagnostic and the new missing-per-key-file
diagnostic are collected there instead of always going straight to
`stderr`; repeats of the same missing file collapse to one entry (a
`std::find`-guarded push, since a pack has at most a few dozen keys -- no
need for a hash set). When `warnings` is null, `load_pack` prints them
itself (`"keeby: %s\n"`), preserving the old direct-print behavior for any
caller that doesn't ask for the vector. `EngineController::set_profile` and
`main.cpp`'s startup `load_profile` both now pass a vector and print it
themselves, same format.

**`keeby --check-profiles`.** A new startup-time special case (alongside
`ctl`, checked before any signal handler/settings/D-Bus/engine setup):
loads every profile from `list_packs()` (plus the built-in `default`) with
no audio, input, or D-Bus touched, and prints one line per pack --
`ok <id>` with any warnings indented underneath, or `error <id>: <msg>` --
exiting 0 if every profile loaded, 1 otherwise. Safe to run against a
live pack directory while the real `keeby` service is running (it only
reads `config.json` and the referenced audio files). Verified against all
18 real packs: every one now reports `ok` (exit 0); the four above show
their warnings (`skipped ... key code(s)` for the two `eg-*` packs and
`nk-cream`, the six missing-file lines for `mxblue-travel`).

## Runtime switching: the RT-safe bank swap

`SoundBank`s are externally owned. `SampleMixer` (src/sample_mixer.hpp)
keeps only `std::atomic<const SoundBank*> requested_bank_` and `active_bank_`
(both `static_assert`-checked lock-free) plus its own single, permanently-
owned `initial_bank_` (the bank passed to its constructor -- e.g. the
built-in default, or whatever profile a CLI `--profile` picked at startup).
Every later bank is owned by `AudioBoundary::retired_`
(`std::vector<std::unique_ptr<const SoundBank>>`), never by `SampleMixer`.

**RT side** (`SampleMixer::sync_bank`, called once per `mix()` callback,
src/sample_mixer.cpp:168): one acquire load of `requested_bank_`. If it
differs from `bank_` (the RT thread's own cached pointer, touched only by
this thread, so it needs no synchronization itself): cut every voice
(`voices_ = {}`, a fixed 32-slot array assignment, no allocation), reset
both per-key history arrays (`.fill(0xff)`, fixed 465-byte arrays), adopt
the new pointer, then a release store to `active_bank_`. This happens
*before* that callback's voices are mixed, so no `Voice::data` pointer into
the about-to-be-superseded bank ever survives past the switch.

**Control side** (`AudioBoundary::swap_bank`, src/audio_boundary.cpp;
called by `EngineController::set_profile` under `lifecycle_mutex_`, which
also serializes `start()`/`stop()` against both `swap_bank()` and each
other -- see "Lifecycle serialization" below): the new bank is moved into
`retired_` first (so it's owned before anything can reference it), then
published via `request_bank`. If the stream is running, poll `active_bank()`
against a 500 ms deadline (1 ms `sleep_for` between polls); if the stream
was never started (or already stopped), apply the switch synchronously via
`sync_bank()` instead -- no wait needed, since nothing can be reading
`bank_` concurrently.

**Pruning rule -- only once `active_bank() == raw` (this exact request) is
observed:** free every OTHER retired bank. This relies on the coherence
guarantee C++ gives a single atomic object: the RT thread's successive
*loads* of `requested_bank_` (always by that same one thread) can never
observe values out of publish order, so once it has settled on `raw`
(`active_bank_ == raw`), it can never later settle on anything *older*.
Every other entry in `retired_` -- including ones left over from an earlier
timed-out `swap_bank()` call -- is therefore now provably unreachable.

On a **timeout**, `swap_bank()` frees *nothing*, not even entries that are
neither `raw` nor the current `active_bank()`. An earlier draft of this
pruning rule freed everything except `requested_bank()`/`active_bank()` on
every call, reasoning that the RT thread "jumps straight to the latest
request, never an intermediate one" -- that reasoning was wrong: on a
timeout, `active_bank()` can still be an *older* request the RT thread
hasn't even loaded past yet, not necessarily `raw` and not necessarily
anything already retired either, and the RT side never skips ahead, it only
ever acts on whatever `requested_bank_` holds at the moment it happens to
call `sync_bank()`. Freeing "everything but the two named pointers" could
therefore free a bank the RT thread had not reached yet but was about to.
Fixed: free nothing on timeout; pruning happens on a later successful
(acknowledged) swap, or in `stop()`.

**`stop()`** (src/audio_boundary.cpp): once the RT thread is confirmed
stopped (`pw_thread_loop_stop` has joined it, or it was never started),
`stop()` calls `mixer_.sync_bank()` to apply any still-pending request
synchronously (identical to `swap_bank()`'s own "not started" branch), then
frees every retired bank *except* whatever `mixer_.active_bank()` now is.
An earlier version called `retired_.clear()` unconditionally, which could
free the very bank `bank_`/`active_bank_` still pointed to; since
start()/stop()/start() is a supported restart cycle (tests/
engine_controller_test.cpp exercises it, and Step 2.7's review added a
dedicated swap-then-restart-then-trigger test to tests/
audio_boundary_test.cpp), the next `mix()` after restart would then read
freed memory. The bank `SampleMixer` was constructed with (`initial_bank_`)
is never in `retired_` and stays owned by `SampleMixer` regardless.

### Lifecycle serialization (`EngineController`)

`AudioBoundary` documents an "owner serializes" contract: `started_` and
`retired_` have no locking of their own, and `swap_bank()` reads/writes both.
`EngineController::lifecycle_mutex_` (src/engine_controller.hpp) is held
across the whole body of `start()`, the whole body of `stop()` (also reached
from the destructor), and just the `swap_bank()` call inside `set_profile`
-- so a profile switch on one thread (e.g. a future tray/D-Bus handler) can
never race a `stop()`/`start()` cycle on another. This is deliberately a
*second*, separate mutex from `profile_mutex_` (which guards only the
`profile_` string, always held briefly): `profile()` -- read from the tray's
D-Bus thread -- takes only `profile_mutex_`, so it is never blocked behind
`swap_bank()`'s up-to-500 ms RT-ack wait or a slow `stop()`/`start()` cycle,
only behind another thread's brief string assignment.

### RT-safety audit (everything Step 2.7 added to the RT path)

Only `SampleMixer::sync_bank()` (called from `mix()`) runs on the audio
callback thread; `swap_bank()`, `request_bank()`'s caller, and `set_profile`
all run on the calling (control) thread only.

- **Allocation**: none. `voices_ = {}` and the two `.fill(0xff)` calls are
  fixed-size array operations; the atomic load/store pair are plain
  `std::atomic<const SoundBank*>` ops (`static_assert`ed lock-free).
- **Locks**: none. No mutex is ever taken on this path (`lifecycle_mutex_`/
  `profile_mutex_` are both control-side only, in `EngineController`).
- **Syscalls / filesystem / logging**: none.
- **Exceptions**: none of `sync_bank`'s operations can throw; the function
  is `noexcept`.
- **Unbounded work**: `sync_bank` does at most one atomic load, and, only on
  an actual switch (rare -- a user action, not per-callback), one 32-element
  array assignment plus two 465-byte fills -- all fixed-size, independent of
  bank content size.
- **Use-after-free**: prevented by construction -- the RT thread only ever
  reads through `bank_`, reassigned (by itself) strictly before the control
  thread can observe the corresponding `active_bank_` release-store (which
  happens-after the reassignment in program order on the same thread) and
  act on it; the acquire/release pairing on both `requested_bank_` (publish)
  and `active_bank_` (acknowledge) makes the handshake correct under the
  C++ memory model, not just "correct in practice."

## Supervisor review: three swap-lifecycle bugs found and fixed

A supervisor review of the first patch approved the loader, path-safety
checks, limits, key mapping, `main.cpp`, and this document's format/pipeline
sections, but found three correctness bugs in the swap lifecycle (all fixed
in the sections above -- this is a pointer to what changed and why, not a
repeat of the detail):

1. **`swap_bank`'s pruning freed banks the RT thread hadn't reached yet.**
   The original rule freed everything except `requested_bank()`/
   `active_bank()` after *every* call, including a timed-out one, reasoning
   that the RT thread always jumps straight to the latest request. It
   doesn't -- on a timeout it may still be sitting on an older request.
   Fixed to prune only once `active_bank() == raw` is actually observed,
   and to free nothing at all on a timeout.
2. **`stop()` could free the bank the mixer was still using.**
   `retired_.clear()` was unconditional; a restart (`start()` after `stop()`,
   a supported cycle) would then mix from freed memory on the next trigger.
   Fixed to sync any pending request first, then prune everything except
   whatever the mixer is actually pointing at.
3. **No serialization between `set_profile` and `start()`/`stop()`.**
   Both touch `AudioBoundary`'s `started_`/`retired_`, which have no locking
   of their own; a future tray/D-Bus-driven `set_profile` racing a
   shutdown-time `stop()` would be a data race. Fixed with
   `lifecycle_mutex_`, kept separate from the string-only `profile_mutex_`
   so a `profile()` read never waits behind a swap.

A fourth item, `scripts/fetch-mechvibes-packs.sh`'s "only that one
subdirectory is fetched" claim, was inaccurate: `git fetch --depth 1`
without a filter downloads every blob in that commit regardless of sparse
checkout (sparse-checkout only limits what gets *checked out* afterwards).
Fixed by adding `--filter=blob:none` to the fetch, so blobs outside the
sparse path are genuinely never downloaded.

## Limitations / explicitly out of scope

- v3/v4 Mechvibes configs and the incompatible mechvibes-dx dialect are
  rejected, not translated.
- No pack management UI: switching profiles at runtime is a library API
  (`EngineController::set_profile`) exercised by tests, but nothing in the
  tray/D-Bus menu calls it yet (out of scope for this step; `--profile` at
  startup and `--list-profiles` cover the brief's CLI requirement).
  `scripts/fetch-mechvibes-packs.sh` is the only user-facing pack tooling
  added.
- Packs are never bundled, committed, or fetched automatically; the fetch
  script is opt-in, asks for confirmation, and is a personal-use convenience
  only (most Mechvibes community packs carry no explicit license).
- `normalize_pack_loudness` is a single global scale per pack, not
  per-key/per-clip loudness matching.
- No caching of decoded packs across runs; every `--profile`/`set_profile`
  re-decodes and re-resamples from disk.
