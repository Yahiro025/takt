# Step 2.8b: wiring the tray menu, control service, single instance and settings

## 1. Goal

Steps 2.4-2.8 merged a tray icon (`tray_service`), a full DBusMenu
(`dbus_menu`), a `keeby ctl` control service (`control_service`), a
single-instance guard, and persisted settings (`settings`), but `main.cpp`
never used most of them: the tray had no menu, `keeby ctl` had nothing to
talk to, two `keeby` processes could run at once, and every setting reset to
its default on restart. This step wires all of it into the running app.

## 2. What the user gets

- **Left-click** the tray icon: toggle sound on/off (unchanged from 2.4).
- **Right-click** (or however the host exposes a StatusNotifierItem's menu):
  a full menu -- see below.
- **Middle-click** (`SecondaryActivate`): quit.
- **Scroll** over the icon: volume ±5 percentage points per notch.
- `keeby ctl ...` from a terminal or a keybinding, while `keeby` is running.
- Settings (enabled, volume, stereo width, profile) survive a restart.
- Only one `keeby` runs at a time; a second launch prints a message and
  exits instead of fighting the first for the keyboard/audio/tray.

## 3. Tray menu

`TrayService` publishes a `com.canonical.dbusmenu` object at `/MenuBar` and
advertises it through the StatusNotifierItem's `Menu` property (`ItemIsMenu`
stays `false`, so left-click still toggles rather than opening the menu).
Contents, built by the pure, unit-tested `build_tray_menu()`
(`src/tray_service.hpp`/`.cpp`):

| Item | Kind | Id |
|---|---|---|
| Sound on | checkmark | 1 |
| Volume: NN% (submenu) | container | 10 |
| &nbsp;&nbsp;25% / 50% / 75% / 100% | radio | 11-14 |
| Stereo width: NN% (submenu) | container | 20 |
| &nbsp;&nbsp;Mono 0% / Narrow 50% / Normal 100% / Wide 150% / Extra wide 200% | radio | 21-25 |
| Switch: \<current name\> (submenu) | container | 30 |
| &nbsp;&nbsp;one radio per available profile | radio | 100 + index |
| &nbsp;&nbsp;"More sounds: run keeby-fetch-packs" (only default installed) | disabled hint | 31 |
| (separator) | separator | 40 |
| Quit | standard | 41 |

A volume/width radio is checked when the live value is within 0.025 of the
preset (so e.g. a scroll-adjusted 0.51 still shows "50%" checked). Profile
clicks are resolved against `last_profiles_`, the exact
`available_profiles()` snapshot the currently-displayed menu was built
from, via `dispatch_tray_menu_click(id, profiles, actions)` -- not a
fresh list -- so a click can't land on the wrong pack if the list changes
between menu build and click. `TrayService::refresh()` rebuilds the menu
and re-emits `NewTitle` after Activate, Scroll, a menu click, and (via the
`on_change` callback `main()` passes to both `TrayService` and
`ControlService`) after every `keeby ctl` call, so all three surfaces
(tray icon, tray menu, ctl) always agree.

## 4. `keeby ctl` reference

Unchanged from the already-merged `control_service.cpp` (`run_ctl`), now
reachable because `main.cpp` dispatches to it before anything else:

```
keeby ctl toggle          flip enabled on/off
keeby ctl on / off        enable / disable sound
keeby ctl volume <0-100>  set volume percent
keeby ctl volume +N|-N    adjust volume by N percentage points
keeby ctl width <0-200>   set stereo width percent
keeby ctl profile <id>    switch sound profile
keeby ctl profiles        list available profile ids
keeby ctl status          print enabled/volume/width/profile
keeby ctl quit            tell the running instance to exit
keeby ctl help            show usage (no D-Bus call, safe to run any time)
```

Exit codes: `0` ok, `1` call failed, `2` KEEBY not running, `64` usage
error. `keeby ctl help` never touches D-Bus.

### niri keybinding example

Until Step 2.9 packages `keeby` onto `PATH`, bind the absolute path of the
built binary, e.g. (adjust the path to your build directory):

```
binds {
    Mod+Shift+K { spawn "/home/yahiro/Documents/PROJECTS/KEEBY_LINUX/build/release/keeby" "ctl" "toggle"; }
}
```

## 5. Settings file

`Settings` (`src/settings.hpp`): `enabled` (bool), `volume` (float,
`[0,1]`), `stereo_width` (float, `[0,2]`), `profile` (string). Location:
`$XDG_CONFIG_HOME/keeby/settings.ini`, or `~/.config/keeby/settings.ini`
if unset. Plain `key = value` lines, `#` comments, unknown keys ignored
with a warning:

```
enabled = true
volume = 1
stereo_width = 1
profile = default
```

Directory created mode `0700`, file written mode `0600`, atomically
(temp file in the same directory, `fsync`d, then `rename()`d over the
target, then the parent directory itself `fsync`d so the rename is
crash-durable -- see review fix 3 below).

Startup precedence for the profile: `--profile` (CLI flag) > `settings.profile`
> `"default"`. Warnings from a malformed settings file go to stderr. If the
resolved profile fails to load, `main()` falls back to `"default"` and marks
settings dirty so the corrected value gets persisted.

**Dirtiness and saving**: a single `std::atomic<bool> settings_dirty` in
`main()`. Every mutating path -- the tray's Activate/Scroll/menu-click
handler and every `ControlService` mutating call (`SetEnabled`,
`SetVolume`, `SetStereoWidth`, a successful `SetProfile`) -- goes through
the same `refresh_and_mark_dirty()` closure, which sets the flag (and, if a
tray exists, rebuilds its menu). The main 500&nbsp;ms poll loop does
`settings_dirty.exchange(false)` and saves only if it was set, so a burst of
scroll events costs at most one write per half-second, and the write always
happens on the main thread -- never the D-Bus event-loop thread or the RT
audio thread. A final unconditional save happens once more at exit, after
`engine.stop()`.

## 6. Single instance

`main()` creates one shared session-bus connection before loading any sound
pack or starting the engine, then calls `acquire_instance_name(*bus)`
(`org.keeby.Keeby`). If another `keeby` already owns that name, it prints
`keeby: already running — use \`keeby ctl ...\`` and exits `3` before
touching audio or input -- a distinct code (Step 2.9) so
`packaging/keeby.service`'s `RestartPreventExitStatus=3` can tell "another
instance is already running" apart from a real crash and skip restarting
into a restart loop against itself. If the session bus itself is unreachable, `keeby`
prints a warning and runs anyway with no tray, no control service, and no
instance guard -- exactly the old "tray unavailable" degradation, just
covering all three D-Bus-dependent features instead of only the tray.

## 7. Connection ownership and shutdown order

One `sdbus::IConnection` (`bus`), owned by `main()`, is shared by
`TrayService` (SNI at `/StatusNotifierItem` + its `DBusMenu` at
`/MenuBar`) and `ControlService` (`/org/keeby/Keeby`); neither owns or
drives it. Every object is exported first (`TrayService::start()`, then
`ControlService`'s constructor) and only then does `main()` call
`bus->enterEventLoopAsync()` once -- so every D-Bus method handler across
all three objects runs serialized on that single event-loop thread,
alongside `EngineController`'s own thread-safe control surface (atomics for
enabled/gain/width, a mutex for `profile()`/`set_profile()`). A profile
switch from a menu click or `keeby ctl profile` therefore runs synchronously
on that thread and can briefly block it (per `EngineController::set_profile`'s
existing up-to-~0.5s RT handshake) but never blocks the RT audio thread.

Shutdown, triggered by SIGINT/SIGTERM or a quit request: `bus->leaveEventLoop()`
first (no handler can start touching `engine`/`tray`/`control` afterward),
then `control.reset()`, then `tray.reset()` (which tears down its `DBusMenu`
too), then `engine.stop()`, then the final settings save.

## 8. Review fixes folded in

- **`dbus_menu.cpp`**: removed `.withNoReply()` from the `Event` method
  registration -- a host that calls `Event` and waits for a reply would
  otherwise time out; an empty reply once `on_event()` returns is always
  safe. `dbus_menu_test`'s live round trip (which calls `Event` via
  `dontExpectReply()` from the client side, independent of this) still
  passes.
- **`control_service.cpp` (`run_ctl`)**: the proxy is now built from an
  explicit `sdbus::createSessionBusConnection()` handed into
  `createLightWeightProxy(std::move(connection), ...)`, instead of the
  connection-less overload, which resolves the bus via `sd_bus_open`'s
  heuristic (the system bus for root or other non-session contexts).
- **`settings.cpp`**: floats are parsed with `std::from_chars` (locale
  independent, unlike `strtof`, which reads the C locale's decimal point);
  a settings file that exists but can't be opened (permissions, etc.) now
  appends a warning instead of silently falling back to defaults exactly
  like a missing file; after `rename()`, the parent directory is opened
  `O_RDONLY|O_DIRECTORY`, `fsync`d and closed (best-effort -- a failed
  directory fsync doesn't turn a successful rename into a reported failure).
- **`input_capture.cpp`**: `errno` is copied into a local immediately after
  the `access(X_OK)` check fails, before the error string is built, so
  nothing in between can clobber it.

## 10. Deviations / things worth a second look

- **`ControlService` read-only handlers**: `get_state` and `list_profiles`
  do *not* call `refresh_and_mark_dirty()`. Only the mutating handlers
  (`SetEnabled`, `SetVolume`, `SetStereoWidth`, a successful `SetProfile`)
  do. Marking settings dirty on a pure status/profiles query would make a
  polling status-bar widget cause a disk write every 500ms for no reason;
  `quit` sets the running flag only, since the unconditional save at exit
  already covers it.
- A failed `load_profile()` (whether from a bad settings file or a bad
  `--profile` flag) always falls back to `"default"` and marks settings
  dirty; the task text called this out specifically for the
  settings-sourced case, but the code path is shared and the behavior
  seems right either way.
- The 0.025 "close enough to a preset" tolerance is specified in the task
  for volume; stereo width (a `[0,2]` range vs. volume's `[0,1]`) uses the
  same absolute tolerance, since none was specified separately and the
  presets are spaced 0.5 apart (no ambiguity near any boundary).

## 11. Known limitations

- No live/manual verification against quickshell/noctalia was possible
  from this isolated worktree (per the task, the real `keeby` binary is
  never run here); the menu was only exercised through `dbus_menu_test`'s
  and `control_service_test`'s live-bus round trips plus the new pure-logic
  `tray_menu_test`.
- The tray menu has no "About"/version item and no way to rename or delete
  a pack from the menu -- out of scope for this step.
- `keeby ctl` still uses a 2-second D-Bus call timeout (unchanged); a
  profile switch that takes longer than that (a very large pack) will
  report a client-side timeout even though the server-side switch may
  still complete.
